# 010 · 任务看板（/pisa status）

- 状态：implemented
- 关联：README「用法」中的 `/pisa status`；P1 的「任务级隔离，可查看状态」只落到最近 5 条原始记录，看不出在跑什么、跑多久、结果在哪
- 依赖：无

## 1. 问题

现在的 `/pisa status` 只把最近 5 条任务按行列出 `任务号 · 状态 · 分支 · 创建时间`。请求者真正要回答的是三个问题：

1. 现在有什么在跑，跑了多久？
2. 还有多少在排队？
3. 最近做完的任务结果如何，PR 在哪？

三组信息混在一列里，还要自己换算时间和去翻 PR，看板必须按这三组分开给出。

## 2. 目标

- 一条消息回答「在跑什么、排多少、最近结果、总量」
- 时间统一人类可读：`42s` / `3m12s` / `2h5m`
- 需求文本单行截断，长的不会把整屏撑破
- 空分组显示「(无)」，不发空标题

## 3. 用户故事

### US-1 看当前负载

作为请求者，我发 `/pisa status`，看到每个运行中任务的任务号、仓库、已运行时长和需求前 40 字。

### US-2 看排队

作为请求者，我看到排队数量和最多 5 条排队任务，知道还要等多久。

### US-3 看结果

作为请求者，我看到最近 5 条完成任务的终态、耗时、仓库、需求前 30 字，有 PR 的附带链接，可以直接点开评审。

### US-4 看总量

作为维护者，我在看板末尾看到总数、成功、失败、暂停四个数字，判断系统整体健康度。

## 4. 需求

| ID | 需求 |
| --- | --- |
| FR-001 | `Store.recentTasks(limit)`：按 `created_at` 倒序取任务，返回完整 `Task`，至少覆盖 `id`、`status`、`repo`、`prompt`、`createdAt`、`startedAt`、`endedAt`（看板里的「完成时间」，即需求中的 finishedAt）、`prUrl` |
| FR-002 | `Store.runningTasks()`：当前 `status = 'running'` 的任务，按 `created_at` 升序（取代原 `listRunning`，启动恢复共用同一方法） |
| FR-003 | `Store.queuedTasks()`：当前 `status = 'queued'` 的任务，按 `created_at` 升序（先来先跑） |
| FR-004 | `Store.recentFinished(limit)`：终态（`succeeded` / `failed` / `cancelled`）任务，按 `created_at` 倒序，供「最近完成」用，避免先取最近 N 条再过滤导致漏项 |
| FR-005 | `Store.countByStatus()`：返回六种状态各自的数量，看板汇总行用；total 为六项之和 |
| FR-006 | `formatDuration(ms)` 纯函数：`< 1m` 输出 `Ns`；`< 1h` 输出 `XmYs`；其余输出 `XhYm`；负数按 0 处理 |
| FR-007 | 看板分三段，段内空列表输出「(无)」：**运行中** 每行 `任务号 · 仓库 · 已运行 <时长> · 需求前 40 字`；**排队** 标题带数量，最多列 5 条，每行 `任务号 · 仓库 · 需求前 40 字`；**最近完成** 最多 5 条，每行 `状态 · 耗时 · 仓库 · 需求前 30 字 · PR 链接`（无 PR 时省略链接段） |
| FR-008 | 运行时长从 `startedAt`（缺失时退化为 `createdAt`）算到当前时间；完成耗时从 `startedAt`（缺失时退化为 `createdAt`）算到 `endedAt` |
| FR-009 | 状态词用中文：`succeeded` 成功、`failed` 失败、`cancelled` 取消 |
| FR-010 | 需求文本先压缩换行与连续空白为单空格再截断，超长时截断处补 `…` |
| FR-011 | 末尾固定一行汇总：`汇总：<总数> 个任务 · 成功 <n> · 失败 <n> · 暂停 <n>` |
| FR-012 | 没有任何任务时仍输出完整三段与汇总（全为「(无)」和 0），不再单独回「还没有任务」 |

## 5. 验收

1. `formatDuration`：`42_000 → 42s`、`60_000 → 1m0s`、`192_000 → 3m12s`、`3_600_000 → 1h0m`、`7_500_000 → 2h5m`
2. 存在运行中任务时，看板文本包含该任务号、`已运行 <时长>` 和需求前 40 字
3. 一条成功任务带 PR 时，看板文本包含该 PR 链接
4. 汇总行数字与库中各状态计数一致
5. `recentTasks(2)` 最多返回 2 条且按创建时间倒序
6. `bun test` 与 `tsc --noEmit` 通过

## 6. 非目标

- 分页、按仓库/请求者过滤
- 运行中任务的实时刷新（每次发命令才拉一次）
- 展示任务日志、摘要全文
- 暂停任务单独成段（只在汇总里计数）
