# 015 · 外部动作 Outbox（幂等交付）

- 状态：approved
- 关联：改进项 `seed:idem-outbox`；013-rewind 的副作用账本
- 范围：一个 feature，一次只做这一个

## 1. 问题

推送分支、创建 PR、回帖都是进程内的同步调用。动作已经在远端生效、数据库里的结果还没写，进程在这一刻崩溃（或被重启、被杀、网络断开），重跑就会对同一任务再建一个 PR、再推送一次、再发一条评论。现在的重试只有人工重投：没有退避，错误原因只留在日志里，重启后也不会自动补做。

复现（改造前代码）：同一任务连续交付两次、中间不写 `tasks.pr_url`，`gh pr create` 被调用两次，得到两个 PR。

## 2. 目标（可度量）

- 同一任务同一动作最多成功执行一次：重跑、重启、重投都不产生第二个 PR、第二次推送、第二条评论。
- 动作先持久化再执行；进程在任意时刻崩溃，重启后未完成的动作自动继续。
- 失败按 2s→60s 指数退避重试；最近一次失败原因可从库里读到。
- 推送/PR 的临时失败不再把已经完成代码改动的任务打成 `failed`。

## 3. 非目标

- 不引入外部消息队列或 broker。
- 不做跨机器接管；Outbox 只服务单机常驻进程。
- 不改变任务状态机与现有命令语义。
- 不做动作的撤销；撤销仍由 `rewind` 负责。

## 4. 用户故事

### US-1 崩溃后不重复建 PR

作为仓库维护者，我不希望同一个任务出现两个 PR。

- **Given** 任务已推送分支，PR 已创建但结果还没落库
- **When** 进程重启后同一任务再次交付
- **Then** 复用已存在的 PR，`gh pr create` 不再执行，任务拿到同一个 PR 链接

### US-2 临时故障自动恢复

作为请求者，我不希望因为一次网络抖动或令牌过期就导致任务失败并手工重投。

- **Given** 推送或回帖因临时错误失败
- **When** 外部条件恢复
- **Then** 队列在退避期满后自动重试，成功后账本与回执与一次成功的情况一致

### US-3 重启接管未完成的动作

作为运维者，重启进程不应丢失已经发生的失败重试计划。

- **Given** 库里存在未完成且到期的动作
- **When** 新进程启动
- **Then** 它在后台接手继续执行，不需要人工触发

## 5. 功能需求

- **FR-001** 持久化动作：一条动作记录包含种类、去重键、载荷、尝试次数、下次可执行时间、最近错误、成功结果、创建与完成时间。
- **FR-002** 入队幂等：同一「种类 + 去重键」只有一条记录，重复入队不新增记录、不覆盖首次载荷。
- **FR-003** 去重键：推送为「分支名@提交号」，PR 为「仓库别名:分支名」，回帖为「仓库#编号:PR或Issue:任务号」。
- **FR-004** 交付中的推送与 PR、任务完成后的回帖都必须经由队列执行，不再直接调用外部命令。
- **FR-005** 成功结果落库；之后同一键的重放直接返回该结果，不再执行外部命令。
- **FR-006** PR 动作执行前先查该分支是否已有 PR；存在则复用它的链接。
- **FR-007** 失败时尝试次数加一，下次执行时间 = 当前时间 + min(2s × 2^(n-1), 60s)，并记录错误摘要。
- **FR-008** 后台按固定间隔执行到期且未完成的动作；进程启动后即开始接手。
- **FR-009** 只有动作成功后才写副作用账本；失败或重试中不入账。
- **FR-010** 推送失败不再让任务失败：交付返回「未推送」与对比链接，任务照常成功，动作留在队列里重试。

## 6. 验收场景

- **AC-1**（US-1/FR-005/FR-006）库里有一条未完成的 PR 动作、远端已有同分支 PR：重放执行后 `gh pr create` 调用次数为 0，记录的结果是已有 PR 链接。
- **AC-2**（US-1/FR-002）同一任务带新改动连续交付两次、`prUrl` 未持久化：PR 创建只发生一次，两次交付返回同一链接。
- **AC-3**（US-2/FR-007）同一动作连续失败 7 次：等待时长依次为 2s、4s、8s、16s、32s、60s、60s，未到期不重试。
- **AC-4**（US-3/FR-008）新队列实例在同一份库上运行：未完成的动作被执行一次，已完成的动作不再执行。
- **AC-5**（FR-009）动作成功后账本出现对应条目；失败期间账本没有该条目。
- **AC-6**（FR-010）远程不可用时交付不抛错，任务成功、动作按退避重试，修好远程后自动推送成功。

## 7. 边界

- 退避没有次数上限：持续失败的动作会一直每小时（60s 封顶）重试一次，直到手动清理记录。
- 载荷在首次入队时冻结；同一键的后续交付不会更新 PR 正文。
- 队列只保证「至多成功执行一次 + 重放安全」，不保证动作按入队全局有序（按记录顺序扫描，一次一个）。
