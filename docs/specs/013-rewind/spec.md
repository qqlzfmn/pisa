# 013 · 任务撤销（rewind）

- 状态：implemented
- 关联：001（任务状态机与 `parseCommand` 入口语法）、006/007（PR 与 Issue 回帖）、011（多仓库 PR 地址）
- 依赖：git、`gh`

## 1. 问题

pisa 做完一个任务会留下分支、远程分支、PR、回帖和合并提交，但没有任何记录说明「这个任务到底做了什么」。做错一次只能手工 `gh pr close` + `git branch -D` + `git push --delete`，漏一步就留下垃圾；已合并的任务更无从下手，因为 `reset` 会改写共享历史。误输入（如 `/pisa stats`）也会走同一条路，事后无法一键回退。

## 2. 目标

- 任务把对外副作用写进账本，可查询、可清理
- `/pisa rewind <任务号>` 只读预览：关哪个 PR、删哪些分支、是否已合并、哪些动作不可撤销
- `/pisa rewind <任务号> --yes` 才执行
- 已合并的任务生成 revert 提交，不用 reset
- 无法确认 PR 状态时不删分支，避免毁掉已合并成果

## 3. 用户故事

### US-1 先看清再动手

作为任务发起者，我输入 `/pisa rewind t_1`，pisa 列出将关闭的 PR、将删除的本地/远程分支、任务是否已合并、以及已发评论这类无法撤回的动作，并给出执行命令。

### US-2 一键回退

作为任务发起者，我加 `--yes` 重发，pisa 关闭 PR、删除远程与本地分支、移除工作副本，任务标记为「已撤销」。

### US-3 已合并任务

作为任务发起者，我撤销一个已经合入 `main` 的任务，pisa 在 `main` 上生成 `revert: 撤销 <任务号>` 提交，原提交保留在历史里。

### US-4 部分失败可重试

作为任务发起者，网络或 gh 故障导致某一步失败时，pisa 报出失败的步骤，成功的步骤不回滚，账本里只留未完成的副作用，修好后重发 `--yes` 继续。

## 4. 需求

| FR-001 | 新增 `task_effects(task_id, kind, target, detail, created_at)` 表，`kind` ∈ `branch` / `push` / `pr` / `comment` / `worktree` / `merge`；`Store` 提供 `effect`、`effectsOf`、`removeEffect` |
| FR-002 | 账本只记录仍然存在的副作用：交付成功、失败清理、取消清理时删掉对应 `worktree` / `branch` / `push` 行；未提交的回帖与已合并的 PR 行保留 |

| FR-005 | 新增终态 `rewound`，只可由 `succeeded` / `failed` / `cancelled` 迁入；状态板显示「已撤销」 |

| FR-007 | `planRewind` 为纯只读函数：由任务、账本与探测点（分支存在、工作副本存在、PR 状态）推出动作列表、不可撤销清单与保留说明 |
| FR-008 | 预览输出合并状态（已合并 / 未合并-PR 打开 / 未合并-PR 已关闭 / 未开 PR / 无法确认）、逐条动作、不可撤销项、保留项，并提示执行命令 |
| FR-009 | `applyRewind` 逐条执行，失败不中断后续；成功动作对应的账本行删除，失败的保留 |
| FR-010 | 已合并：优先按 `merge` 账本记录的 `{base, from, to}` 做 `git revert --no-commit from..to`；缺区间时退回 `gh` 报告的合并提交（合并提交加 `-m 1`）；要求主工作区在 `base` 分支 |
| FR-011 | PR 状态无法确认（`gh` 失败）时不删分支、不标记 `rewound`，输出「未完成」并提示修正后重试 |
| FR-012 | 只有原请求者能撤销；运行中的任务要求先 `cancel`；已撤销的任务重复撤销只回复提示 |
| FR-013 | 交付幂等：推送后在 `gh pr create` 之前用 `gh pr list --head <branch> --state open` 认领同分支上已有的开放 PR，命中则复用其链接、不再新建；改动已提交（无待提交文件）且任务无 `prUrl` 时，分支已在 origin 上也要先认领一次 |

## 5. 验收

1. 任务结束后 `effectsOf(id)` 反映实际留下的副作用，交付清理掉的 `worktree` 不再出现
2. `/pisa rewind <id>` 不改动仓库与 PR，只输出预览，包含将关闭的 PR、将删除的分支、合并状态与不可撤销项
3. `/pisa rewind <id> --yes` 关闭 PR、删除远程与本地分支、移除工作副本，并清掉对应的账本行
4. 已合并任务撤销后 `main` 上多一条 `revert: 撤销 <id>` 提交，文件回到合并前
5. 部分失败时任务不标记 `rewound`，账本只留失败项；修好后重发 `--yes` 完成
6. `gh` 不可用时分支被保留，任务不标记 `rewound`
7. 分支上已有开放 PR 而任务 `pr_url` 为空（上次崩溃在记账之前）时，交付复用该 PR、不调用 `gh pr create`，任务收尾后 `pr_url` 非空且账本有对应 `pr` 行

## 6. 非目标

- 撤销 worker 执行期间的其它外部调用（API、消息、数据库）：账本只覆盖分支、推送、PR、回帖、工作副本、合并
- 删除已发评论：GitHub 不保证可删，只标注不可撤销
- 远程分支删除的强制回滚与误删恢复
- 自动撤销：任何动作都要人或 agent 显式带 `--yes`
