# 012 · 任务统计（/pisa stats）

- 状态：implemented
- 关联：README「用法」；P1 的「任务级隔离，可查看状态」只回答「现在在跑什么」，看不出长期健康度：成功率、平均耗时、仓库分布、近期吞吐
- 依赖：010 的状态看板（`countByStatus`、`formatDuration`）

## 1. 问题

`/pisa status` 面向当下：运行中、排队、最近五条。维护者想知道的是另一组问题：

1. 这个系统整体成功率如何？
2. 一个任务平均要跑多久？
3. 任务落在哪些仓库，各自成功多少？
4. 最近一周每天的产出是多少？

这些是聚合数据，混进看板会把当下信息淹没，需要单独的只读命令。

## 2. 目标

- 一条消息回答「总量与成功、平均耗时、仓库分布、最近 7 天完成量」
- 口径明确：成功率只算已结束任务；平均耗时只算成功任务；按天统计按本地时区的结束时间
- 空库也能回答，不出现 `NaN`、`null` 或空段

## 3. 用户故事

### US-1 看健康度

作为维护者，我发 `/pisa stats`，看到总量与各状态数量、成功率、成功任务平均耗时。

### US-2 看仓库分布

作为维护者，我看到每个仓库的任务数与成功数，按任务数倒序，最多 5 行，其余用一行说明。

### US-3 看近期吞吐

作为维护者，我看到最近 7 天（含今天）每天结束的任务数，0 也显示，便于判断是否停摆。

## 4. 需求

| ID | 需求 |
| --- | --- |
| FR-001 | `parseCommand` 识别 `stats` / `统计`，返回 `kind: "stats"`；私聊里 `/stats`、`统计` 同样生效 |
| FR-002 | `Store.stats(since)` 返回四项聚合：六种状态计数、成功任务平均耗时（毫秒，无则 `null`）、按仓库的 `{repo, total, succeeded}`（任务数倒序，同数按仓库名）、`since` 之后按本地日期分组的已结束任务数 `{day, n}` |
| FR-003 | 已结束指 `succeeded` / `failed` / `cancelled`；计数口径与 `countByStatus` 一致，总量为六项之和 |
| FR-004 | 成功率 = 成功数 / 已结束数，四舍五入到整数百分比；已结束为 0 时显示 `—` |
| FR-005 | 平均耗时基于 `succeeded` 任务的 `ended_at - coalesce(started_at, created_at)`；无成功任务时显示 `—` |
| FR-006 | 「最近 7 天」从本地时间今天 0 点往前 6 天起算，按 `ended_at` 落在范围内、状态为终态计数 |
| FR-007 | 报告分段：首行标题 `任务统计`；总量行；成功率行；平均耗时行；`按仓库` 段；`最近 7 天完成` 段 |
| FR-008 | 仓库段最多列 5 行，超出时末行 `其余 <n> 个仓库未列出`；无任务时输出 `(无)` |
| FR-009 | 每天一行 `MM-DD · <数量>`，7 天固定全列 |
| FR-010 | 帮助文本包含 `stats` 一行 |

## 5. 验收

1. 空库执行 stats：包含 `总量 0`、`成功率 —`、`平均耗时 —`、`(无)`、7 个日期行
2. 两条成功任务耗时 2m 与 20m、一条失败、一条运行中：成功率 `67%（2/3）`，平均耗时 `11m0s`
3. 仓库段按任务数倒序，成功数与状态一致
4. 今天完成 2 条时，今天的日期行显示 2，其余为 0
5. `bun test` 与 `tsc --noEmit` 通过
