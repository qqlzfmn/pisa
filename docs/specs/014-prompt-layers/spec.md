# 014 · 提示词分层与版本

- 状态：implemented
- 关联：001（Worker 提示词与内置约束）、005（恢复段）、012（命令清单）
- 依赖：无

## 1. 问题

Worker 提示词（角色、恢复段、上一轮上下文、任务、约束/评审标准）逐行写在 `src/adapters/omp.ts` 的 `buildPrompt` 里。改一条约束要改代码、发版、重启；团队无法按自己的仓库规范调整评审标准，也无从知道自己的措辞和内置版本差在哪。

## 2. 目标

- 提示词拆成具名段落，内置值放在 `prompts/builtin.json`，带版本号
- 团队层 `prompts/team.json` 只写要覆盖的段落，未覆盖的段落回退内置
- 启动时加载并校验：未知顶层键、未知段落键、非法版本、未知占位符都拒绝启动，并指出文件与键
- `/pisa prompts` 展示分层与版本，`/pisa prompts diff` 展示覆盖内容与行级差异
- 覆盖只改文件，不改代码

## 3. 用户故事

### US-1 团队改约束不改代码

作为团队维护者，我在 `prompts/team.json` 里改写 `constraints` 段并标记版本号，重启后所有新任务的提示词使用我的版本，其余段落仍用内置。

### US-2 改动可追溯

作为团队成员，我发 `/pisa prompts` 看到内置 v1、覆盖 v2 以及每个段落的生效来源；发 `/pisa prompts diff` 看到逐行差异，不用读代码。

### US-3 非法配置不静默生效

作为运维，我把段落键拼错成 `constraint`，进程启动即失败，报错说明是哪个文件的哪个键、可用键有哪些，而不是带着半套提示词跑任务。

## 4. 需求

| ID | 需求 |
| --- | --- |
| FR-001 | 段落键固定为 `intro`、`resume`、`context`、`task`、`constraints`，拼接顺序即此顺序，段落之间空一行 |
| FR-002 | `prompts/builtin.json` 形如 `{ "version": 正整数, "segments": {...} }`，必须定义全部段落；缺文件或缺失段落视为启动错误 |
| FR-003 | `prompts/team.json` 可选，形如 `{ "version": 正整数, "segments": {...} }`，`segments` 至少一项且只能包含已知段落键；未覆盖的段落取内置值 |
| FR-004 | 两个文件都只能有 `version`、`segments` 两个顶层键；段落值必须是非空字符串 |
| FR-005 | 段落支持占位符 `{{id}}`、`{{prompt}}`、`{{context}}`；出现其它占位符视为配置错误 |
| FR-006 | 配置错误在启动时抛出，错误信息包含文件路径与出错的键名；进程以非零码退出 |
| FR-007 | `resume` 段只在恢复执行时出现；`context` 段只在任务带上一轮上下文时出现；其余段落每轮都出现 |
| FR-008 | 没有覆盖层时生成的提示词与改造前逐字节一致 |
| FR-009 | `/pisa prompts` 输出内置版本、覆盖版本（无覆盖时标明）、目录、每个段落的生效来源；`/pisa prompts diff` 输出被覆盖段落的行级差异，无覆盖时说明全部使用内置 |
| FR-010 | 命令行参数错误时回复用法提示，不建任务 |

## 5. 验收

1. `prompts/` 目录存在 `builtin.json`（带 `version`），缺文件或缺段落时启动失败
2. `team.json` 写了未知顶层键或未知段落键时启动失败，报错含键名
3. `/pisa prompts` 显示版本与来源；`/pisa prompts diff` 显示 `-`/`+` 行
4. 只改 `prompts/team.json` 即改变 Worker 提示词，无需改代码
5. 测试覆盖：拼接顺序、无覆盖回退默认、非法配置拒绝、恢复/上下文段的条件出现、diff 输出

## 6. 非目标

- 按仓库分层的覆盖（本次只有内置层与团队层）
- 改文件热重载：覆盖变更重启后生效
- 段落内条件语法与模板逻辑
