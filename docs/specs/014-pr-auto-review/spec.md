# 014 · PR 自动评审

- 状态：implemented
- 关联：006/007（PR 与 Issue 回帖、去重与回帖标记）、008（本地仓库别名）、011（多仓库 PR 地址）
- 依赖：git、`gh`

## 1. 问题

pisa 只能用代码换 PR，评审仍靠人。目标仓库里新开的 PR 可能几天没人看，作者也不知道改动有没有问题。把评审交给 pisa 的关键难点不是「能不能评」，而是三条边界：评审不许留下任何提交或分支、同一份代码不许重复评、开关关掉后不许再产生任务。

## 2. 目标

- 配置开关打开后，轮询目标仓库的开放 PR，发现新的 head 提交就派一个评审任务
- 评审任务只读：不提交、不推送、不开 PR，工作副本用完即弃
- 评审结论以评论形式回帖到该 PR
- 同一 PR 的同一 head 提交只评审一次，进程重启后也不重复
- 草稿 PR 不评审
- 开关关闭时既不拉取 PR 列表也不建任务

## 3. 用户故事

### US-1 新 PR 自动得到评审

作为仓库维护者，我打开评审开关后，别人开了一个 PR。pisa 在一轮轮询内派任务，任务结束把结论评论到 PR 上，我能直接看到阻塞问题与建议。

### US-2 不重复打扰

作为 PR 作者，我 rebase 过或只是改了评论，head 提交没变，就不再收到第二份评审；只有推了新提交才重新评审。

### US-3 评审不动代码

作为仓库维护者，我要求评审任务绝不产生分支、提交或推送。即便评审模型试图写文件、提交或推送，仓库也不应出现这些改动。

### US-4 可关闭

作为运维，我删掉评审开关，pisa 停止拉取开放 PR 列表，也不再产生评审任务；已经产生的评审任务照常跑完。

## 4. 需求

| ID | 需求 |
| --- | --- |
| FR-001 | 配置新增 `github.review.enabled`，缺省关闭；评审跟随 `github.enabled` 的轮询 |
| FR-002 | 配置新增 `github.repos[].alias`：评审任务在该本地仓库检出代码；未配置时用默认本地仓库 |
| FR-003 | 轮询每轮拉取目标仓库的开放 PR（编号、head 提交、标题、基线分支、是否草稿），拉取失败只记日志不影响评论轮询 |
| FR-004 | 草稿 PR 跳过 |
| FR-005 | 评审任务带独立任务类型 `review`：分支为空、`baseRef` 为 PR 的 head 提交、`replyPr` 为目标 PR |
| FR-006 | 去重键为「仓库 + PR 号 + head 提交」：进程内集合与库内事件占位双重去重；head 提交变化即为新事件 |
| FR-007 | 评审任务的工作副本以分离 HEAD 检出 PR 的 head 提交；工作副本、分支、推送、PR 都不保留 |
| FR-008 | 评审任务的验收条件是运行成功，不检查文件改动；成功后结论以评论回帖，正文带 PR 号与 head 短提交。结论取首行符合「`结论：可以合并` / `结论：有阻塞问题` / `结论：需要讨论`」的助手消息（从最后一条往前找，回帖该消息全文）；找不到就判任务失败、不回帖，错误里带模型的首行 |
| FR-009 | 开关关闭时不调用 PR 列表接口、不建评审任务 |
| FR-010 | 评审任务同样遵守白名单与仓库别名解析，未知别名不建任务 |

## 5. 验收

1. 开关打开、目标仓库有一个新 PR，一轮轮询后库内出现一条 `mode = review` 的任务，`baseRef` 等于该 PR 的 head 提交
2. 同一 head 提交再轮询若干轮，任务数不变；head 提交变化后新增一条
3. 草稿 PR 不产生任务
4. 开关关闭时 PR 列表接口一次都不被调用，任务数为零
5. 评审任务跑完：任务成功、工作副本被删除、本地没有任何 `pisa/<任务号>` 分支、远程分支集合不变、PR 下出现一条带评审标记的评论
6. 评审任务的工作目录确实是 PR 的 head 提交内容
7. 评审任务即使产生文件改动也不会推送、不会建分支
8. 模型的助手消息首行都没给结论时：任务失败、PR 下没有评论，错误消息带模型的首行

## 6. 非目标

- 行级评论（inline review comment）：只发一条 PR 评论
- 自动批准或请求修改（approve / request changes）：结论只作为评论
- 评审 diff 之外的文件：只看 PR 的 head 提交与工作副本
- PR 关闭、合并、重新打开的处理：只判断开放 PR 的 head 提交
- 给评审结论打分或自动修复：发现问题不自动改代码
