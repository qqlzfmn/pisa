# 016 · README 首页化

- 状态：implemented
- 关联：014（能力索引与可执行示例）、015-repo-ops（工程化与文档入口）

## 1. 问题

README 是一份配置说明书：为什么做、架构、快速开始之后，是 webhook、多仓库、主动发现、定时、保留、GitHub 评论、launchd 的逐项配置。访客打开首页看不出它解决什么问题、和自己已经在用的云 bot 有什么区别；30 秒内复制不出一段能跑的命令。

证据：用户原话「一觉醒来代码库就成为一个 trending repo 的样子」，同一条改进项写着「现在 README 是配置说明，不是产品首页」。复现：打开 `main` 的 README，首屏是四枚静态徽章与一段架构图，往下 100 行内没有任何可复制命令；仓库没有 `LICENSE`，没有演示动图，没有和 CNB NPC / Copilot agent 的边界说明。

## 2. 目标

- 首页回答三个问题：这是什么、多久能跑起来、和我现在的工具差在哪
- 30 秒上手的命令块可原样复制并跑通
- 架构图讲清 core / runtime / worker / 入口的边界
- 三个真实场景带预期输出，而不是功能罗列
- 配置细节回到文档，README 保持首页体量

## 3. 用户故事

### US-1 陌生访客

作为第一次点进仓库的人，我在不滚动的情况下读到一句话定位、三类读者路径、演示动图，知道它是不是我要的东西。

### US-2 想立刻试用的人

作为想试的人，我复制「30 秒上手」整块命令，不改任何参数就能看到 `[pisa] ready`，并发出一条需求。

### US-3 已在用云 bot 的人

作为已经用着 CNB CodeBuddy NPC 或 Copilot cloud agent 的人，我能在一张表里看到运行位置、代码托管、触发方式、权限面、单会话上限的差异，判断要不要再引入一套。

### US-4 维护者

作为维护者，我改了文档链接会先被测试拦住，不会等访客发现死链。

## 4. 需求

| ID | 需求 |
| --- | --- |
| FR-001 | 首屏一句话定位 + 三类读者路径（使用者 / 贡献者 / 好奇者） |
| FR-002 | 徽章覆盖 CI、license、Bun 版本，链接指向真实页面 |
| FR-003 | 30 秒上手是可复制命令块，含最小配置与首条需求 |
| FR-004 | 架构图（mermaid）标出入口、core、runtime、worker 及它们之间的唯一契约 |

| FR-006 | 与 CNB CodeBuddy NPC、GitHub Copilot cloud agent 的边界对比表 |
| FR-007 | FAQ 与已知限制 |
| FR-008 | 一张演示 GIF（真实 CLI 通道录制） |
| FR-009 | 配置与运维细节迁到 `docs/operations.md`，README 只留入口 |

## 5. 非目标

- 不改任务执行、调度与交付行为
- 不做英文版或网站
- 不伪造未经实测的能力（如 `gh pr create` 的真实调用）

## 6. 验收

1. README 首屏含定位句与三类读者表
2. 四枚徽章返回 200；CI 徽章指向 `.github/workflows/ci.yml`，license 徽章指向 `LICENSE`
3. 30 秒上手的命令块在干净副本上原样执行，能接单并产出 `pisa/<任务号>` 分支
4. mermaid 图可解析，节点覆盖入口 5 个通道、Router、SQLite、WorkerRunner、adapter、worktree
5. 三个场景都有预期输出，其中场景 1 与 webhook 响应取自实跑记录
6. 边界表的三列与三家平台官方文档一致
7. 已知限制与 `docs/architecture.md` 5.2 一致，不含已解决项
8. `docs/assets/demo.gif` 存在且为动画 GIF
9. 既有测试全绿，`bunx tsc --noEmit` 无报错
