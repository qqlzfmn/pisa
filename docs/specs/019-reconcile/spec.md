# 019 · 资源对账

- 状态：implemented
- 关联：013-rewind（账本与撤销）、探测接口注入的同类结构

## 1. 问题

任务失败、被取消或进程被杀时，pisa 已经建好的资源会留下来：本地分支 `pisa/<任务号>`、`.pisa/worktrees/<任务号>`、推上去的远程分支、开出来的 PR。这些残留目前只能靠人工发现与手工删：

- `/pisa gc` 按「结束超过 N 天」批量清，回答不了「现在到底还剩什么、哪一条是我漏掉的」；
- 手工 `git worktree remove`、`rm -rf`、`git push --delete` 之后，git 的 worktree 登记可能与磁盘不一致，再删分支会被 git 拒绝；
- git 与任务记录是两套事实：盘上有、库里没有的孤儿没有任何出口；
- 成功任务的分支与 PR 是待合并的交付物，批量清理很容易误删。

## 2. 目标

- `/pisa reconcile [任务号]` 一次性列出四类资源与任务记录的差异：本地分支、远程分支、工作副本、PR
- 每条差异标明归属任务与处置结论，可清理的给出动作
- `--fix` 只执行「可清理」项，重复执行无副作用（幂等）
- 运行中、暂停、成功待合并的资源一律不动
- 任务需要工作副本却找不到时反向报出来

## 3. 命令

```
/pisa reconcile              # 全部任务
/pisa reconcile t_xxx        # 只看这个任务号相关的资源
/pisa reconcile --fix        # 先预览后清理，可与任务号组合
```

别名 `对账`，进 Telegram 菜单（`COMMANDS` 是命令清单的唯一事实源，解析、错拼建议、菜单、帮助都从它生成）。

### 处置矩阵

| 归属 | 结论 | `--fix` 行为 |
| --- | --- | --- |
| 没有任务记录 | 可清理 | 删资源 |
| `failed` / `cancelled` / `rewound` | 可清理 | 删资源 |
| `queued` / `running` / `paused` | 保留 | 不动 |
| `succeeded` | 保留（交付待合并） | 不动，按时间的清理归 `gc` |
| 运行中或暂停任务的工作副本缺失 | 缺失 | 只报告 |

### 归属规则

- 工作副本：目录名即任务号。
- 分支：先按任务记录里的 `branch` 精确匹配，再按 `pisa/<任务号>` 反推任务号。
- 非 `pisa/` 前缀且没有任务记录的分支、以及 `baseBranch`，不参与对账（主干与手工分支不归 pisa 管）。
- PR：先按任务记录的 `prUrl` 序号匹配，再按 `headRefName` 反推任务号；两者都不剩的 PR 不是 pisa 建的，忽略。
- git 没登记、但躺在 `.pisa/worktrees/` 下的目录，同样按孤儿处理。

### 外部状态查不到时

- 仓库没有 GitHub 远端、或 `gh pr list` 失败：该仓库产出一条「无法确认」，不带任何 PR 动作。

## 4. 需求

| 编号 | 需求 |
| --- | --- |
| FR-1 | 预览为默认行为，只读探测，不改分支、不删目录、不调 `gh pr close` |
| FR-2 | 差异按「可清理 / 保留 / 缺失 / 无法确认」分组，每行带仓库、资源标识与结论理由 |
| FR-3 | 有可清理项时给出下一步命令（`--fix`），无差异时明确说没有差异 |
| FR-4 | `--fix` 逐条执行、失败不中断后续，失败项带 git/gh 的原始错误并提示重试 |
| FR-5 | 工作副本先让 git 自己摘，摘不掉再删目录，随后 `worktree prune`；否则后续删分支会被 git 以「被工作副本占用」拒绝 |
| FR-6 | 路径比较统一成真实路径（macOS 的 `/var` 指向 `/private/var`），避免把已登记的工作副本当成孤儿 |
| FR-7 | `任务号` 只筛该任务号相关的差异，不影响其它任务的资源 |

## 5. 验收

- 预览：失败任务的本地分支、远程分支、工作副本、PR 都列为可清理；运行中与成功任务的同类资源列为保留；预览后资源原样。
- `--fix`：失败任务的四类资源消失，远程分支在裸仓库里也消失；运行中、成功任务的资源仍在；无任务记录的残留目录被删。
- `--fix` 失败（`gh pr close` 拒绝）：该项标记失败并带错误，其余项照常完成，提示重试。
- `任务号` 过滤：输出只含该任务号，其它任务的资源不受影响。
- 全部测试通过，`bunx tsc --noEmit` 无输出。

## 6. 非目标

- 不做按时间的批量清理（`/pisa gc` 已覆盖）。
- 不清理账本行：rewind 的每个动作都先探测资源是否存在，残留行不会导致误操作；让 reconcile 同时改账本会把两条路径耦合在一起。
- 不接管手工非 `pisa/` 分支，不删主干。
