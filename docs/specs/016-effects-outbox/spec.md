# 016 · 外部动作走 Outbox：推送、建 PR、回帖先落库再执行

- 状态：specified
- 关联：013 撤销（`task_effects` 账本是撤销依据）、006/007 GitHub 回帖、011 多仓库
- 依赖：无新增运行时依赖

## 1. 问题

推送分支、创建 PR、回 PR/Issue 三类外部动作目前都在 `deliverer.deliver` 与 `Router.replyToSource` 里同步调用，执行结果只存在内存里：

- 动作成功、进程在写库前崩溃 → 重启重跑时 `createPr` 再被调用一次，产生第二个 PR（回帖有隐藏标记去重，PR 没有）
- 动作失败 → 异常直接抛给 `runTask`，任务被标 `failed`，没有退避重试的机会；一次网络抖动就丢了一次交付
- 交付结果（分支已推、PR 已建）不是持久事实，只是返回值

复现：同一任务第一次交付建出 `pull/101`，进程在 `transition(succeeded, prUrl)` 前崩溃，恢复后 worker 再改一次文件，第二次交付又建出 `pull/102`。推送目标不可达时 `deliver` 直接抛出 `推送失败: ...`，之后没有任何自动重试。

## 2. 目标

- 三类外部动作先落库再执行，数据库是「要做什么」的唯一事实源
- 同一 `(kind, key)` 只执行一次；动作已生效但进程在标记前崩溃，重放也不产生重复 PR/评论
- 失败按 2s 起、每次翻倍、封顶 60s 的退避重试
- 进程重启后未完成的动作继续执行，已完成的动作不再执行
- 交付结果（`pushed`、`prUrl`）从队列状态读取，而不是从本次调用的返回值猜

## 3. 非目标

- 不做跨进程并发消费（pisa 单进程运行，队列只在宿主进程内跑）
- 不新增动作类型（合并、分支、工作副本仍按现状同步处理，它们已幂等或已有账本）
- 不改回帖的隐藏标记协议、不改 PR 正文格式
- 不清理 effects 历史行（任务行本身长期保留，同一量级）

## 4. 需求

| ID | 需求 |
| --- | --- |
| FR-001 | 新增 `effects` 表：`(kind, key)` 为主键，记录 `task_id`、`payload`、`state`（`pending`/`running`/`done`）、`attempts`、`next_at`、`last_error`、`result`、时间戳 |
| FR-002 | 新增 `EffectQueue`：`enqueue`、`state`、`flush`、`drainDue`、`start`、`stop`，按自动重试需要注册各类动作的执行器 |
| FR-003 | 交付路径的推送与 PR 创建、回帖路径的 PR/Issue 回帖，都改为「入队 → 立即尝试一次」；不再同步直接调用外部命令 |
| FR-004 | 同一 `(kind, key)` 入队只保留一行；已完成的行再次入队不重新执行 |
| FR-005 | 执行失败把 `attempts` 加一，`next_at = 现在 + min(2s × 2^(attempts-1), 60s)`；到期的行由后台循环每秒扫描执行 |
| FR-006 | 启动时把上次进程遗留的 `running` 行退回 `pending`；已到期的 `pending` 行立即参与重试 |
| FR-007 | PR 动作幂等：执行前按 head 分支查询已存在的开放 PR，存在则复用其链接；查询失败视为本动作失败并退避，不当作「没有 PR」 |
| FR-008 | 回帖动作幂等：沿用隐藏标记检查，讨论串已有同标记则视为完成（不重复发） |
| FR-009 | PR 动作依赖同任务的推送动作：推送未完成时 PR 动作推迟重试，避免在分支缺失时建 PR |
| FR-010 | PR 动作成功后把链接写回任务的 `pr_url`，并记 `pr` 账本；推送成功记 `push` 账本（撤销依赖这两条账本） |
| FR-011 | 交付结果：推送动作 `done` 才算 `pushed`；`prUrl` 取任务已有链接或 PR 动作的结果；推送未完成时不回落 compare 链接 |
| FR-012 | 任务被撤销后，该任务未完成的动作不再执行 |

## 5. 验收场景

1. **正常交付**：任务有改动、push 与 pr 开启 → 分支推到远程、PR 创建一次、任务 `succeeded` 且 `prUrl` 为 PR 链接，账本有 `push` 与 `pr`。
2. **崩溃重放不重复建 PR**：PR 已创建但动作行未标 `done`；重启后重放该动作 → 复用已有 PR（按 head 查询命中），`createPr` 不被再次调用。
3. **推送失败退避**：远程不可达 → 交付不抛错、`pushed=false`、任务按现有规则收尾；动作行 `pending`、`attempts=1`、`next_at=now+2s`；`now+1999ms` 不重试，`now+2000ms` 重试；连续失败等待翻倍直到 60s 封顶。
4. **重启续跑**：进程重启后新队列在同一数据库上 `drainDue` → 到期动作执行成功并标记 `done`；上次遗留的 `running` 行被退回 `pending`。
5. **同 key 只执行一次**：同一 `(kind, key)` 第二次入队不新增行，已完成的动作再 `flush` 不触发执行器。
6. **回帖失败只退避、不改任务状态**：回帖命令失败 → 任务仍 `succeeded`、日志记 `回帖失败`，动作行继续 `pending`；讨论串已有同标记时动作直接完成并记日志「已存在同标记回帖，跳过」。
7. **撤销**：撤销成功后该任务未完成的动作行不再被重试。
