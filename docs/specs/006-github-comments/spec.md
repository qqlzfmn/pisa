# 006 · GitHub PR 评论绑定

- 状态：implemented
- 关联：P1「任务与讨论的订阅绑定」中 GitHub 部分；README 当前状态列的「未完成：GitHub PR 评论」
- 依赖：005（中断可续）提供的分支续跑语义

## 1. 问题

目前只有 IM 消息能把新要求送回已有任务：回复机器人消息、或带任务号执行 `continue`。代码评审发生在 PR 评论里，评审人写完意见，还要有人把评论内容手工搬到 IM，才能让 Agent 接着改。搬运是纯损耗：谁搬谁负责，漏搬就断线。

## 2. 目标

- PR 评论里带触发词的留言，能直接把工作推进到仓库，不需要 IM 参与
- 同一条评论只处理一次
- 评论落在某个 pisa 产出 PR 上时，接续那个 PR 的任务继续改，而不是另起炉灶
- 任务完成后，把结果回帖到来源 PR，评审人在原处就能看到答复
- 回帖失败不影响任务本身的状态
- 回帖带隐藏标记：同一任务重复收尾（进程重启后重跑）不产生第二条评论

## 3. 用户故事

### US-1 评审人直接在 PR 里提改法

作为评审人，我在 pisa 产出的 PR 下留言 `/pisa 把超时改成 30 分钟`，系统接着这个 PR 的分支改代码，并把结果回帖到同一条 PR。

### US-2 在没有对应任务的 PR 上开新任务

作为维护者，我在一个没有 pisa 任务的 PR 下留言 `/pisa 补一条测试`，系统照常接单，执行结果回帖到这条 PR。

### US-3 不重复处理

作为维护者，我不想同一条评论被反复处理：网络抖动、进程重启、轮询重叠都不该产生第二个任务。

## 4. 需求

| ID | 需求 |
| --- | --- |
| FR-001 | 配置新增可选的 `github` 段：是否启用、仓库全名（`owner/repo`）、轮询间隔、token 环境变量名、投递用的 chatId 与 userId；未配置或未启用时，系统行为与现在完全一致 |
| FR-002 | 启用后按间隔轮询仓库的 Issue 评论（PR 评论同属其中），只取上次轮询之后新增或更新的评论 |
| FR-003 | 增量下界优先取落库游标（`meta` 表 key `github:since:<repo>`）；没有记录（旧库新启用、新增仓库）时以启动时刻初始化并立即落库，不回放历史评论；整轮成功后把游标推进到本轮开始时刻，失败不推进 |
| FR-004 | 只处理正文去掉首尾空白后以触发词加一个空格开头的评论；其余评论一律忽略，不产生任务、不产生回复 |
| FR-005 | 同一条评论（以 GitHub 评论 id 识别）最多产生一个任务；重复轮询、进程重启、重叠轮询都不得重复建任务 |
| FR-006 | 评论所属 PR 若已有 pisa 任务且该任务已成功，则新任务接续它的分支与上下文；新任务直接在父任务分支上继续，不新建分支、不新建 PR，完成后更新原 PR；上下文必须包含 PR 号与原评论正文 |
| FR-007 | 评论所属 PR 没有可接续任务（或该任务未成功）时，按普通任务处理，需求正文为去掉触发词后的内容 |
| FR-008 | 由 PR 评论产生的任务，完成后把摘要回帖到来源 PR；摘要超过 3000 字时截断 |
| FR-009 | 回帖失败只记录日志，任务状态与回执不变 |
| FR-010 | 轮询或解析失败不中断进程，下一轮继续；失败不推进增量下界，避免漏评论 |
| FR-011 | 进程关停时停止轮询 |
| FR-012 | 接续任务的失败、取消清理只针对任务自建的分支（`pisa/<任务号>`）；复用父任务分支的任务不得删除该分支 |
| FR-013 | 目标任务分支已被其它工作副本占用时，任务失败并报告占用原因，不得另建同名分支顶替 |
| FR-014 | 回帖正文末尾追加隐藏标记 `<!-- pisa:reply task=<任务号> on=pr -->`（Markdown 注释，渲染不可见）；发送前用 `gh api repos/<repo>/issues/<n>/comments --paginate --jq '.[]'` 逐行解析讨论串正文，已含同标记则跳过不发 |
| FR-015 | 回帖前检查失败（`gh` 非零退出）时不发帖，只记日志：无法确认是否已发时，漏发可重跑补救，重复发不可撤销 |

## 5. 验收

1. 给定配置启用且仓库 `o/r`，当评论正文为 `/pisa 修一下登录` 且 `issue_url` 为 `.../issues/12`，轮询后产生一个任务：需求正文为 `修一下登录`，绑定 PR 12
2. 给定同一评论被连续两轮返回，当两轮轮询结束，只存在一个任务
3. 给定评论正文为 `修一下登录`（无触发词）或 `/pisax`，轮询后不产生任务
4. 给定 `o/r` 的 PR 12 已有成功任务 A（分支 `pisa/A`，prUrl `https://github.com/o/r/pull/12`），当 PR 12 下出现 `/pisa 再改一处`，新任务满足：起点分支与任务分支均为 `pisa/A`，prUrl 为 `https://github.com/o/r/pull/12`，完成后不创建新 PR，上下文含 `#12` 与原评论正文，需求正文为 `再改一处`
5. 给定 PR 12 没有成功任务，当出现 `/pisa 补测试`，产生普通任务，需求正文为 `补测试`
6. 给定任务成功且绑定 PR 12，当任务收尾，向 PR 12 回帖一次，正文以任务摘要开头且不超过 3000 字
7. 给定回帖命令失败（`gh` 非零退出或抛错），任务仍为成功状态，日志留下失败原因
8. 给定 `gh api` 返回非零或输出无法解析，本轮不建任务、不推进下界，进程继续运行
9. 给定启动时刻为 T，当首轮轮询，查询的下界为 T，不处理 T 之前的评论
10. 给定进程关停，轮询定时器停止
11. 给定接续任务复用父任务分支 `pisa/A`，当该任务失败或取消，分支 `pisa/A` 仍然存在；任务自建分支 `pisa/<新任务号>` 才被清理
12. 给定分支 `pisa/A` 已被其它工作副本占用，当任务以该分支启动，任务失败且错误信息包含占用原因，仓库中不出现新分支顶替
13. 给定任务已有 prUrl，当其成功收尾，只推送分支，不调用 `gh pr create`，任务 prUrl 保持原值
14. 给定讨论串里已有带本任务标记的回帖，当任务再次收尾，不执行 `gh pr comment`，日志记录「已存在同标记回帖，跳过」
15. 给定讨论串里没有本任务标记，当任务成功收尾，`gh pr comment` 的正文末尾为 `<!-- pisa:reply task=<任务号> on=pr -->`
16. 给定回帖前的讨论串拉取失败，当任务收尾，不执行 `gh pr comment`，任务仍为成功状态，日志留下检查失败原因
17. 给定库中已有游标 `2026-01-01T00:00:00.000Z`、当前时刻为 2026-11-18，当 Watcher 启动并轮询，查询下界为 `2026-01-01T00:00:00.000Z`；该轮成功后游标变为本轮开始时刻；用同一库重建 Watcher，下界沿用游标而不是重建时刻，同一评论重复投递仍只有一个任务
18. 给定库中没有游标记录，当首轮轮询，下界为启动时刻，且游标以启动时刻落库

## 6. 非目标

- 处理 Issue 评论中的非 PR 讨论（由 007 补齐：普通 Issue 评论从主干开新分支并回帖到 Issue；PR 之外的 Issue 评论不受 006 的回帖路径处理）
- 监听 PR 的其它事件（开、合、review、CI 状态）
- 多仓库轮询：配置只接受一个仓库全名
- 回帖内容的智能排版（只回摘要）
- 白名单以外的权限模型：评论作者不参与鉴权，投递身份由配置的 userId 决定
- 评论删除、编辑后的撤销：已建任务不因评论被编辑或删除而回滚
