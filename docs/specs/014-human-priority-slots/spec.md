# 014 · 追问优先槽位（human priority slots）

- 状态：implemented
- 关联：002（并发 Worker 与 `worker.concurrency`）、010（任务看板）、005（`resume` 恢复）
- 依赖：无

## 1. 问题

002 只提供一个 FIFO 队列和一个并发上限。两个槽位被长任务占满时，人发一句「顺便补个测试」也要排在所有新任务后面，等几十分钟才轮上；而队列里的新任务其实并不急。看板只显示「排队（N）」，看不出卡在哪个槽位、为什么排队。

## 2. 目标

- 槽位变成显式计数：主槽位数、已用数、追问槽位数、已用数都能读出
- 人的追问（`continue`、回复任务消息、`resume`）走独立的追问槽位，满槽也能立即开始
- 新任务不许占用追问槽位，避免把优先通道挤掉
- 看板给出槽位占用与每条排队任务的原因
- `humanSlots = 0` 时退回原来的单队列行为

## 3. 用户故事

### US-1 满槽时追问能插队

作为任务发起者，两个任务正在跑时我补一句 `continue`，它立刻开始，不用等长任务结束。

### US-2 新任务照常排队

作为任务发起者，我知道新任务只排主槽位；空闲的追问槽位不会分给新任务，优先通道始终留给人的追问。

### US-3 看板给出排队原因

作为维护者，我发 `status` 看到「槽位：主 2/2 · 追问 1/1」，每条排队任务都标明「主槽位已满（2/2），等运行中的任务结束」或「追问槽位已满（1/1）」。

### US-4 恢复也走优先通道

作为任务发起者，进程重启后我 `resume` 一个任务，它同样占追问槽位，不被满队列挡住。

## 4. 需求

| ID | 需求 |
| --- | --- |
| FR-001 | 槽位显式计数：`Router.slots()` 返回 `{ limit, used, humanLimit, humanUsed }`；运行中任务的槽位归属记在内存 `active`（`SlotKind = "task" \| "human"`） |
| FR-002 | 两条车道：主槽位上限 `worker.concurrency`（≥1，默认 2）只跑新任务；追问槽位上限 `worker.humanSlots`（≥0，默认 1）只跑人的追问与 `resume` |
| FR-003 | 追问落库：`Task.followUp`（列 `follow_up INTEGER NOT NULL DEFAULT 0`），由 `continue` 命令与回复任务消息的续跑（`continueFrom`）置为 1 |
| FR-004 | 按车道取队：`Store.nextQueued("task" \| "human" \| "any")`，各自 `ORDER BY created_at` |
| FR-005 | 补位顺序：先补追问槽位（`nextQueued("human")`），再补主槽位（`humanSlots > 0` 时 `nextQueued("task")`）；任何一处都不超过自己的上限，新任务不占追问槽位 |
| FR-006 | `resume` 在有追问槽位时占追问槽位，否则占主槽位；对应车道满时回复「当前<车道>已满（used/limit），稍后再恢复」 |
| FR-007 | 看板新增槽位行：`槽位：主 used/limit · 追问 humanUsed/humanLimit`；`humanSlots = 0` 显示 `槽位：主 used/limit（无追问保留，共用队列）`；排队行在需求前插入原因（`主槽位已满（x/y），等运行中的任务结束` / `追问槽位已满（x/y），等运行中的任务结束` / `等待补位（…）` / `进程关停中，暂停补位`） |
| FR-008 | 看板槽位计数以内存为准，并补上未登记在内存的 `running` 任务（重启遗留、直接落库），避免少算 |
| FR-009 | `humanSlots = 0` 退回单队列：追问与新任务共用主槽位按 FIFO 混排（旧行为） |
| FR-010 | 占位仍由 `claimQueued` 原子完成（`queued → running`），槽位计数不作为并发控制依据 |

## 5. 验收

1. `slots()` 在两条车道占用时返回正确的四个数
2. 两个主槽位占满时，`continue` 生成的追问任务进入 `running`，`humanUsed = 1`
3. 同一场景下新任务保持 `queued`，不占用空闲的追问槽位
4. 追问槽位被占后第二条追问排队；`/pisa status` 同时显示槽位行与两条不同的排队原因
5. `humanSlots = 0` 时追问与新任务按创建顺序在主槽位执行
