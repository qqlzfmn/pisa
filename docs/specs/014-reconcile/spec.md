# 014 · 残留对账（reconcile）

- 状态：implemented
- 关联：001（命令入口与任务状态机）、012（账本 `task_effects`）、013（rewind 的探测/执行分层）
- 依赖：git、`gh`

## 1. 问题

任务失败、取消或进程中断后，分支、远程分支、worktree 与 PR 可能只清掉一部分；手工回退和 `rewind` 都要求先知道任务号，不知道残留属于谁就只能逐个仓库翻。DB 里的账本也可能指向早已被删掉的资源，导致后续预览出现幽灵项。

## 2. 目标

- 用一个命令核对 DB 任务记录与磁盘、远程、GitHub 的实际状态
- 默认只读列出差异；确认后带 `--fix` 执行清理
- 正在执行的任务资源绝不被清理
- 已成功任务的交付物（分支、远程分支、PR）保留，可供合并或续跑
- 账本与真实状态对齐：资源确认不存在时删除对应记录

## 3. 用户故事

### US-1 全局体检

作为运维者，我输入 `/pisa reconcile`，pisa 扫描全部任务，列出无主的分支/worktree/PR，以及失败任务留下的残留，并给出 `--fix` 命令。

### US-2 单任务核对

作为任务发起者，我输入 `/pisa reconcile t_20261118_ab12`，只查看这个任务相关的差异；即使 DB 没有该任务记录，同名残留也会被列出。

### US-3 安全清理

作为运维者，我带 `--fix` 重发。pisa 逐项删除失败任务与无主资源；运行中任务的资源出现在「保留」区，不会被删。

## 4. 需求

| ID | 需求 |
| --- | --- |
| FR-001 | 新增命令 `reconcile`（`/pisa reconcile [任务号] [--fix]`，私聊可用 `/reconcile`），进 Telegram 菜单，带正文参数 |
| FR-002 | `planReconcile` 为纯只读函数：由任务列表、账本与探测点（本地分支、远程分支、worktree、打开的 PR）推出动作、保留项与无法确认项 |
| FR-003 | 资源归属按名称中的任务号：本地/远程分支 `pisa/<任务号>`、worktree `<stateDir>/worktrees/<任务号>`、PR 的 head 分支；无法解析出合法任务号的资源不处理 |
| FR-004 | 任务号在 DB 中存在时按状态决策：`queued`/`running`/`paused` 一律保留；`succeeded` 保留分支、远程分支与 PR，只回收 worktree；`failed`/`cancelled`/`rewound` 清理全部资源 |
| FR-005 | 任务号在 DB 中不存在时视为孤儿，清理其分支、远程分支、worktree 与打开的 PR |
| FR-006 | 无参数扫描全部任务；带参数只核对一个任务号，仍会报告该号的孤儿资源 |
| FR-007 | 查询失败不猜测：远程不可达或 `gh` 不可用时，对应类别进入「无法确认」，不产生清理动作 |
| FR-008 | 账本核对：对已结束任务，`worktree` 路径不存在、本地分支不存在、远程分支不存在时删除账本行；运行中任务不删账本 |
| FR-009 | 预览输出范围、逐条动作、保留项、无法确认项，并提示带任务号与 `--fix` 的执行命令 |
| FR-010 | `applyReconcile` 逐项执行，失败不中断后续；成功的动作同步删除对应账本行，失败的保留以便重试 |
| FR-011 | 删除动作必须验证结果：worktree 目录仍存在、本地分支仍可解析、远程删除返回非零、PR 关闭失败都算失败 |
| FR-012 | 仅白名单用户可执行，避免任意成员清理仓库资源 |
| FR-013 | 工作副本被 `git worktree lock` 时视为人工保护：该任务的分支、远程分支、PR 与账本一律保留，不产生删除动作 |
| FR-014 | 目录已被删但 git 仍留有登记的工作副本，清理动作只执行 `worktree prune` 并校验登记消失；`gh` 缺失或不可执行时按「无法确认」处理，不抛异常 |

## 5. 验收

1. `/pisa reconcile` 不修改仓库、worktree、PR 或账本，只输出差异
2. 失败任务留下的本地分支、远程分支、worktree、打开的 PR 出现在可清理列表；运行中任务的同类资源出现在保留列表
3. `/pisa reconcile --fix` 删除可清理项，保留项不受影响；再次执行时列表为空
4. 无 DB 记录的 `pisa/t_*` 分支与 `worktrees/t_*` 目录被列为孤儿并可清理
5. 资源已被手工删除时，账本行在 `--fix` 后被移除
6. 远程或 `gh` 不可用时输出「无法确认」，不删除任何东西

## 6. 非目标

- 恢复已删除的资源
- 清理非 `pisa/` 前缀的分支或非任务号命名的 worktree
- 处理多个远程：只核对 `origin`
- 自动定时对账：由人或 agent 显式触发
