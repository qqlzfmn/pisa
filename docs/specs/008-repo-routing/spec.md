# 008 · IM 多仓库路由

- 状态：implemented
- 关联：README「多仓库」；`Config.repos` 已支持多个别名，但入口无法指定用哪一个
- 依赖：无

## 1. 问题

`repos` 配置本来就能写多个仓库，但入口消息只能落到默认仓库（`repos[0]`）。想对第二个仓库派活，只能改配置重启，或者干脆再部署一份 pisa。多仓库实际上只有一份配置是「真的在用」。

## 2. 目标

- 在私聊、群聊、触发词三种入口里，用 `@别名 需求` 指定仓库
- 别名不在配置里时行为不变：走默认仓库，正文原样保留
- 接单回执明示实际仓库，发指令的人不用猜
- 帮助文本能让人发现这个语法

## 3. 用户故事

### US-1 群聊里指定仓库

作为维护者，我在群里发 `/pisa @family 改一下首页`，任务落在 `family` 仓库，需求正文是「改一下首页」。

### US-2 私聊裸文本指定仓库

作为维护者，我在私聊里直接发 `@family 改一下首页`（不带触发词），任务落在 `family` 仓库。

### US-3 别名写错时不被静默改写

作为维护者，我发 `@nope 做X`，系统不会把它当成仓库前缀吞掉：仍然走默认仓库，需求正文保持 `@nope 做X`。

### US-4 确认落到哪个仓库

作为维护者，任务接单时回执里能看到 `仓库：<别名>`，不用回忆默认仓库是哪个。

## 4. 需求

| ID | 需求 |
| --- | --- |
| FR-001 | 消息正文（去掉首尾空白）匹配 `^@([A-Za-z0-9_-]+)\s+([\s\S]+)$` 且别名存在于 `repos` 时，本次消息的仓库改为该别名，正文改为别名之后的剩余内容；之后照原逻辑继续解析（触发词、私聊免触发词一并生效） |
| FR-002 | 触发词形式同样支持：`<触发词> @别名 需求` 先去掉触发词再识别前缀，效果等同直接发 `@别名 <触发词> 需求`；正文不含别名 |
| FR-003 | 别名不存在（或没有跟随正文）时不做任何改写：仓库仍取默认仓库，正文原样进入后续解析 |
| FR-004 | 任务受理回执包含一行 `仓库：<实际别名>` |
| FR-005 | 帮助文本包含一行说明 `@别名 需求` 的用法 |
| FR-006 | 只识别消息开头的一个别名；正文中间出现的 `@别名` 不参与路由 |
| FR-007 | 一次任务只落一个仓库；别名解析结果写入任务记录与后续工作副本、交付链路使用同一个仓库 |

## 5. 验收

1. 给定 `repos` 含 `family`，当群聊收到 `/pisa @family 改一下首页`，产生一个任务：仓库为 `family`，需求正文为 `改一下首页`
2. 给定 `repos` 含 `family`，当私聊收到 `@family 做X`，产生一个任务：仓库为 `family`，需求正文为 `做X`
3. 给定 `repos` 不含 `nope`，当群聊收到 `/pisa @nope 做X`，任务仓库为默认仓库，需求正文为 `@nope 做X`
4. 给定 `repos` 含 `family`，当接单回执发出，正文包含 `仓库：family`
5. 给定触发词 `/pisa`，当发出 `/pisa help`，帮助正文包含 `@别名`
6. 给定群聊且未开私聊免触发词，当收到 `@family 做X`（不带触发词），不产生任务（沿用群聊规则）
7. 给定双仓库配置 `demo`（默认）与 `family`，当两种形式各发一次，两个任务分别落 `demo` 与 `family`，不会互相串仓库

## 6. 非目标

- 别名之外的仓库寻址方式（编号、路径、全名）
- 一条消息同时派给多个仓库
- 别名的大小写归一或模糊匹配：按配置原样精确匹配
- 别名与其后正文之间只有一个空格时的特殊处理（要求有分隔空白）
- 在 GitHub 评论、webhook、主动发现里使用别名前缀（各自的仓库来源已确定）
