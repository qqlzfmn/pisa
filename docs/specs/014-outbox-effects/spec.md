# 014 · 外部动作 Outbox（effect 队列）

- 状态：implemented
- 关联：001（交付流程）、006/007（PR 与 Issue 回帖）、011（多仓库）、013（副作用账本 `task_effects`）
- 依赖：git、`gh`、SQLite

## 1. 问题

推送、建 PR、回帖都是同步调用：先做动作，成功后才落库。进程在「动作完成」与「状态落库」之间崩溃时，重启后任务仍是 running / paused，恢复或重跑会把同一件事再做一遍——重复 PR、重复评论、重复推送。失败也没有重试：`gh` 临时不可用或网络抖动，动作直接丢掉，只在任务日志里留一行。

## 2. 目标

- 外部动作先落库再执行：崩溃后重启能接着做没做完的动作
- 同一 `(kind, key)` 只执行一次，重复入队复用已有结果
- 失败按 2s→60s 指数退避重试，次数用尽标 `failed` 并保留错误
- 重放不影响任务状态机：动作重试成功，任务照常收尾

## 3. 用户故事

### US-1 崩溃不产生重复 PR

作为维护者，进程在推送成功后崩溃，重启后分支不会重复建 PR：`pr` 动作按 `(仓库, 分支)` 去重，第二次入队直接拿到上次的 PR 地址。

### US-2 评论不会发两遍

作为任务发起者，回帖动作按 `(仓库, 号, 任务号)` 去重；即使进程在发帖前后崩溃，重启重放也只留一条评论（回帖正文本身还带隐藏标记，双保险）。

### US-3 gh 抖动自动重试

作为维护者，`gh` 临时失败时 `push` / `pr` / `comment` 按 2s、4s、8s、16s、32s、60s 退避重试，不需要人工再点一次。

## 4. 需求

| ID | 需求 |
| --- | --- |
| FR-001 | `effects` 表：`(kind, dedupe_key)` 唯一，记录 `payload`、`status`（pending/done/failed）、`attempts`、`next_at`、`result`、`error`、时间戳 |
| FR-002 | `EffectQueue.enqueue(kind, key, payload)` 先落库再执行；行已 `done` 时直接返回上次结果，不再执行 |
| FR-003 | 同一进程内同 `(kind, key)` 并发入队共享同一次执行 |
| FR-004 | 执行失败按 `base·2^(n-1)` 退避，封顶 60s；默认最多执行 7 次（2s→60s 全阶梯），用尽标 `failed` |
| FR-005 | `replay()` 取 `pending` 行继续执行；启动时调用，返回重放条数 |
| FR-006 | `stop()` 中断等待，未完成的动作保持 `pending`，留给下次启动重放 |
| FR-007 | 交付器：`push` 以 `(仓库, 分支, HEAD)` 为键、在仓库主路径执行；`pr` 以 `(仓库, 分支)` 为键，结果即 PR 地址 |
| FR-008 | 回帖走同一队列：`comment` 以 `(仓库, 号, 任务号)` 为键，执行体仍是 `postReplyOnce` |
| FR-009 | 关停打断交付时任务不标 failed、不清理工作副本，保持 running 交下次启动分流 |

## 5. 验收

1. 同一 `(kind, key)` 入队两次，执行体只跑一次，两次调用拿到同一结果
2. 已完成的行再次入队不触发执行，直接返回 `result`
3. 执行体连抛失败时按 2000/4000/8000/16000/32000/60000ms 退避，用尽后行标 `failed` 且带最后一条错误
4. 进程崩溃模拟：入队失败后新建队列调 `replay()`，未完成动作继续执行并落 `done`
5. `stop()` 之后的入队返回未成功、行保持 `pending`，下次启动可重放
6. 端到端：把 gh 打坏的用例在退避耗尽后任务仍 `succeeded`，日志记「回帖失败」
7. `bun test`、`bunx tsc --noEmit` 通过

## 6. 非目标

- 跨进程分布式锁：单进程轮询模型，`UNIQUE(kind, dedupe_key)` 足以去重
- 动作的强制撤销：`task_effects` 账本负责可逆操作，Outbox 只管「做过没有」
- 队列可视化面板与手工重放命令
- 非 push/PR/回帖的外部调用（消息发送、webhook）沿用原有尽力而为语义
