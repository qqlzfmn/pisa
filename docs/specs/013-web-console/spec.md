# 013 · Web 控制台（Phase 1）

- 状态：implemented
- 关联：改进项 `seed:web-ui-1`；用户原话「为了最大限度高效直观地使用 pisa core，搞一个 pisa web 或 pisa app」
- 依赖：010 任务看板、012 命令防护（派活沿用同一套误触保护）

## 1. 问题

pisa 的全部能力只有 IM 命令这一个入口。定位一个任务要去翻聊天记录，看日志要直接打开 `.pisa/logs/<任务号>.log`，比较多个任务的状态只能靠 `/pisa status` 的五行文本。任务数量一多，这套交互就无法支撑日常使用。

## 2. 目标

- 在浏览器里一屏看到运行中、排队、最近完成的全部任务，并按仓库筛选
- 点开单个任务能看到需求全文、状态、耗时、分支、PR 链接与日志尾部
- 在页面上派活、取消、合并，合并前必须二次确认
- 只有持有 token 的本机请求能访问；未授权请求被拒绝
- 单页、零前端框架、无构建步骤

## 3. 用户故事

### US-1 看当前负载

作为使用者，打开控制台就看到三组任务（运行中 / 排队 / 最近完成）与各状态计数，不需要再发 `/pisa status`。

### US-2 盯一个任务的日志

作为使用者，点开任务卡片，看到需求原文、状态、耗时、分支、PR 链接和最近日志行；日志随执行推进自动刷新。

### US-3 在页面上派活

作为使用者，在页面输入需求并选择仓库，提交后立刻看到「已接单」和新任务号，任务走与 IM 完全相同的排队与执行链路。

### US-4 取消与合并

作为使用者，对运行中/排队任务发起取消；对已完成任务发起合并，合并前浏览器弹窗二次确认，合并结果（通过 / 测试失败 / 主干不在目标分支）原样显示。

### US-5 复制任务号

作为使用者，点「复制任务号」把任务号放进剪贴板，用于 IM 续跑或外部脚本。

## 4. 需求

| ID | 需求 |
| --- | --- |
| FR-001 | HTTP 服务只绑定本机回环地址；`GET /ui` 返回单页控制台。`bun run web` 以不使用 IM 通道的方式启动同一套调度与页面；daemon 启动时按配置内置该服务 |
| FR-002 | 所有请求（含 `/ui`）必须携带 token：`Authorization: Bearer <token>`、`x-pisa-token` 头或 `?token=` 查询参数三选一；缺失或不匹配返回 401 |
| FR-003 | token 取配置 `tokenEnv` 指定的环境变量；环境变量为空时读 stateDir 下的 `web_token`，不存在则生成 32 字节随机串并以 0600 写入 |
| FR-004 | `GET /api/tasks[?repo=别名]` 返回运行中任务、排队任务、最近完成（最多 20 条）、六种状态计数与配置里的仓库别名清单；任务附带人类可读耗时 |
| FR-005 | `GET /api/tasks/:id` 返回任务全字段与日志尾部（最近 200 行，按时间/阶段/正文结构化）；日志文件不存在时日志为空数组；任务不存在返回 404 |
| FR-006 | `POST /api/tasks` 接受 `{prompt, repo?}` 派活：需求为空、仓库不在配置中、需求以命令词开头时返回 400 且不建任务；成功返回 201 与新任务。页面产生的回执不投递到 IM 通道 |
| FR-007 | `POST /api/tasks/:id/cancel` 取消任务：排队或中断任务立即变为取消；运行中任务标记取消请求，Worker 进程组整体终止后变为取消；已终态任务返回 409 |
| FR-008 | `POST /api/tasks/:id/merge` 合并任务：沿用 `/pisa merge` 的临时副本测试与 `--ff-only` 合并；只有已成功且有分支的任务可合并，其余返回 409 |
| FR-009 | 控制台按管理员处理写操作：可以取消、合并任何请求者创建的任务。IM 侧仍只允许原请求者 |
| FR-010 | 页面包含：三段看板、仓库筛选、派活表单、任务详情抽屉、手动刷新；自动轮询刷新且不整页重载 |
| FR-011 | 合并前必须二次确认；复制任务号写入剪贴板；取消其它任务同样要求确认 |
| FR-012 | 不引入前端框架与构建步骤，页面为单个 HTML 文件加内联 CSS/JS |
| FR-013 | 默认端口 8798，避开 webhook 的 8799；端口被占用时只告警，不影响 IM、调度与已有任务 |

## 5. 验收

1. 不带 token 请求 `/ui`、`/api/tasks`、`POST /api/tasks` 均返回 401；错误 token 同样 401
2. 带 `x-pisa-token` 或 `Authorization: Bearer` 请求 `/ui` 返回 200 且是 HTML
3. 造出排队、运行中、成功三种任务后，`/api/tasks` 分三组返回，计数与实际一致
4. `?repo=<别名>` 只返回该仓库任务
5. 任务详情返回需求、分支、PR 与日志尾部；日志行能解析出阶段与正文；未知任务 404
6. `POST /api/tasks` 建出 queued 任务；空需求、未知仓库、命令词开头的需求不建任务
7. 取消排队任务后状态为 cancelled；取消已结束任务返回 409
8. 合并成功任务后主干出现该分支的改动；合并未成功任务返回 409
9. 浏览器打开带 token 的地址，能完成看板浏览、派活、取消、合并、复制任务号
10. `bun test` 与 `bunx tsc --noEmit` 通过

## 6. 非目标

- 多用户、账号体系、远端访问、HTTPS 证书
- 日志全文下载、跨任务日志检索、日志实时推送（用轮询）
- 任务续跑、恢复、定时任务管理、仓库配置编辑
- 历史任务分页与全文搜索
- 移动端专门适配、主题切换、国际化
