# 002 · 多 Worker 并行

- 状态：approved
- 关联：README 路线图 P1
- 前置：001-router-worker 已交付

## 1. 问题

P0 同一时刻只跑一个任务。第二件事必须等第一件做完，和「一个对话里同时推进三件事」的目标直接冲突。

## 2. 目标

- 同时执行 N 个任务（默认 2，可配置），互不阻塞
- 每个任务仍有独立工作副本与分支，并行时不会互相踩
- 队列先进先出，空出槽位立刻补位
- 单个任务失败或取消，不影响其他正在跑的任务
- 任一时刻都能看到每个任务的实时状态

## 3. 非目标

- PR 评论与 Worker 的绑定（P2 的订阅层）
- 跨机器调度
- 普通任务之间的优先级插队（人类追问的独立槽位见 019）
- 资源配额（CPU/内存）控制

## 4. 用户故事

### US-1 并行执行

作为请求者，我连续发两个任务，希望它们同时开始，而不是排队等。

- **Given** 并发上限 ≥ 2，队列里有两个任务
- **When** 调度器补位
- **Then** 两个任务在 1 秒内都进入 `running`，各自有独立分支

### US-2 互不影响

作为请求者，其中一个任务失败，另一个要照常完成。

- **Given** 两个任务并行执行
- **When** 任务 A 失败
- **Then** A 进入 `failed` 并回执，B 继续执行直到 `succeeded`

### US-3 状态可见

作为请求者，我要能随时看到在跑什么。

- **Given** 有任务在排队或执行
- **When** 我发 `/pisa status`
- **Then** 返回最近 5 个任务的状态、任务号与分支

## 5. 功能需求

| ID | 需求 |
| --- | --- |
| FR-001 | 并发上限可配置（`worker.concurrency`，默认 2，最小 1） |
| FR-002 | 任务出队与置 `running` 必须原子，避免同一任务被两个槽位取走 |
| FR-003 | 槽位空出后 1 个调度周期内补位 |
| FR-004 | 每个任务独立工作副本与分支（沿用 001） |
| FR-005 | 并行任务之间日志、状态、回执互不串扰 |
| FR-006 | 单任务失败/取消只清理自己的工作副本与分支 |
| FR-007 | `/pisa status` 返回最近 5 个任务：任务号、状态、分支、创建时间 |
| FR-008 | 取消仍是按任务号精确取消，不影响同批其他任务 |

## 6. 非功能需求

| ID | 需求 |
| --- | --- |
| NFR-001 | 两个任务并行时，总耗时不超过单个任务耗时的 1.5 倍 |
| NFR-002 | 并发数超过上限时，多出的任务保持 `queued`，不丢 |
| NFR-003 | 进程退出时等待在跑任务收尾（SIGTERM 后最多 10 秒） |

## 7. 验收

1. 连发两个任务 → 两个都在 1 秒内 `running`，分支不同
2. 任务 A 失败 → B 仍 `succeeded`
3. 并发上限设为 1 → 行为与 P0 一致，串行执行
4. `/pisa status` 能看到全部任务
