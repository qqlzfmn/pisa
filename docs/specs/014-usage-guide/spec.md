# 014 · 能力索引与可执行示例

- 状态：implemented
- 关联：001（任务入口与 `parseCommand`）、009（定时任务）、006/007（GitHub 评论）、012（命令误触防护）

## 1. 问题

现有文档只说明安装与命令清单，读者无法判断「什么场景该用它、怎么用效果最好、哪些事不该交给它」。

证据：用户原话「我无法准确定位这个工具，没有具体的使用实例」。复现：`/pisa examples` 在实现前不被识别为命令，落入单英文词防护并要求 `confirm`；`/pisa help` 只按命令行逐条罗列，没有场景与边界。

## 2. 目标

- 入口能直接给出可照抄的场景，而不是要求读者自己把命令拼成用法
- 帮助按用途分组，先回答「我该用哪类入口」
- 能力边界写进文档，避免把 pisa 当聊天机器人或 CI 执行器

## 3. 用户故事

### US-1 找得到场景

作为第一次使用的人，我发 `/pisa examples`，得到 6–8 个场景，每个都写明触发方式与预期产出，我可以直接复制触发语句。

### US-2 按用途找命令

作为已经用过的人，我发 `/pisa help`，按「派活 / 查询 / 维护 / 集成」四组看到全部入口，不必逐行扫命令表。

### US-3 知道不该用它做什么

作为评估者，我打开 `docs/usage.md`，能看到无沙箱、撤销不完整、单机、并发上限、鉴权面这些边界，并知道替代做法。

## 4. 需求

| ID | 需求 |
| --- | --- |
| FR-001 | 新增命令 `examples`（别名 `示例`，私聊可用 `/examples`），不接收正文参数 |
| FR-002 | `examples` 输出 6–8 个场景，每个包含场景名、可直接复制的触发方式、预期产出；末尾指向 `docs/usage.md` |
| FR-003 | 场景覆盖：单任务派活、多仓库、续跑、状态与取消、撤销、自举合并、CI 事件投递、PR 评论派活 |
| FR-004 | `/pisa help` 按「派活 / 查询 / 维护 / 集成」分组输出，命令名来自 `COMMANDS`，不另建命令表 |
| FR-005 | `docs/usage.md` 包含场景用法、最佳实践、能力边界（无沙箱、回滚范围、单机、并发、鉴权面） |
| FR-006 | README 的用法段落链接到 `docs/usage.md` |

## 5. 非目标

- 不改任务执行、调度与交付行为
- 不做交互式向导或命令自动补全

## 6. 验收

1. `/pisa examples` 不建任务，输出场景数在 6–8 之间，每块都有触发与产出
2. `/pisa help` 输出四个分组标题，`COMMANDS` 中每条命令都出现在对应分组里
3. `docs/usage.md` 存在且覆盖五类边界
4. README 有指向 `docs/usage.md` 的链接
5. 既有测试全绿，`tsc --noEmit` 无报错
