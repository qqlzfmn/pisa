# 022 · 提示词分层与版本

- 状态：implemented
- 关联：001（Router/Worker 拆分）、020（PR 自动评审）
- 依赖：无

## 1. 问题

Worker 与 PR 评审的提示词写死在 `src/adapters/omp.ts` 与 `src/pr-review.ts` 里。团队想调评审判据（比如按仓库补充检查项）或改 Worker 的约束段，只能改代码、发版；也没法回答「线上跑的是哪一版提示词、改了什么」。

## 2. 目标

- 提示词正文是数据，放在仓库的 `prompts/` 目录，带版本号
- 团队可以只覆盖其中几段，或者追加自己的段落，不改代码
- 启动时加载并校验；配错直接拒绝启动，报错指出哪个提示词、哪一段、哪个键
- `/pisa prompts` 能看版本、段落来源与相对内置的 diff

## 3. 需求

| ID | 需求 |
| --- | --- |
| US-1 | 维护者改 Worker 的约束段或评审判据，只改 `prompts/` 下的文件，重启生效 |
| US-2 | 评审标准按仓库定制：团队目录里放同名段落文件即可覆盖，其它段落仍用内置 |
| US-3 | 排查线上提示词：`/pisa prompts` 看版本与覆盖情况，`/pisa prompts <id> diff` 看差异 |
| FR-001 | 提示词按 id 组织，每个 id 有段落清单与版本号；段落顺序由清单决定 |
| FR-002 | 段落支持条件渲染：`when` 指向一个模板变量，变量为假时整段不出现（如 `resume`、`context`） |
| FR-003 | 段落正文支持 `{{变量}}` 占位；变量集合由代码按提示词 id 提供，正文出现未知变量视为配置错误 |
| FR-004 | 团队层可选：按 id 提供 `prompt.json`（版本 + 新增段落声明）与同名段落文件；同名段落替换内置正文，新增段落追加在内置顺序之后 |
| FR-005 | 团队目录缺省、或目录不存在时只用内置提示词（回退默认）；目录存在但内容非法时拒绝启动 |
| FR-006 | 非法配置：未知提示词 id、未知段落键、清单里的未知键、非正整数版本、缺段落文件、未声明的段落文件、未知占位符、未知 `when` 变量，全部拒绝并指明位置 |
| FR-007 | 配置项 `prompts.dir` 指定团队目录，相对配置文件所在目录解析 |
| FR-008 | `/pisa prompts`、`/pisa prompts <id>`、`/pisa prompts <id> diff` 三个形态；未知 id 回可用列表；diff 为逐行 `-`/`+` 对比，新增段落全部标 `+` |
| NFR-001 | 提示词渲染保持现有文案与顺序；没有团队覆盖时，Worker 与评审任务的文本与改动前一致（除空行拼接差异） |
| NFR-002 | 加载失败只发生在启动或测试，不在任务执行中途抛错 |

## 4. 验收

1. 只给内置 `prompts/` 时，Worker 提示词按 role → task → guard 顺序出现；`resume: true` 时插入恢复段，有 `context` 时插入上下文段
2. 团队目录覆盖 `guard` 并新增 `team-rules` 段时，渲染顺序为 role → … → guard（团队正文）→ team-rules；未覆盖的段落仍是内置正文
3. 团队目录不存在、或团队清单不含覆盖时，使用的就是内置正文与版本号
4. 未知提示词目录、未知段落文件、清单未知键、`version: "1"`、未知 `{{var}}`、未知 `when` 均抛 `PromptConfigError`，消息包含出错路径或键名
5. `/pisa prompts` 列出每个 id 的内置版本与团队版本；`/pisa prompts worker diff` 输出覆盖段的 `-`/`+` 行；无覆盖时说明「当前即内置提示词」
6. `bun test` 与 `bunx tsc --noEmit` 通过

## 5. 非目标

- 提示词的 A/B 实验、按任务灰度和热更新：改动只在启动时加载
- 用模型生成或自动优化提示词
- 通过 IM 改写提示词（只读查看；编辑走文件 + 配置项）
- 内置提示词的多语言版本
